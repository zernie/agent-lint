# Demo — `vigiles scaffold-test` writes the test from a typed spec

This is the tangible answer to _"what does a typed `.spec.ts` give me that markdown
can't?"_ — **the spec generates a runnable test you'd otherwise hand-write.**

The agent here ([`agents/reviewer.md`](agents/reviewer.md), compiled from the typed
spec at [`../railway/reviewer.md.spec.ts`](../railway/reviewer.md.spec.ts)) declares
two things in code that a markdown `description:` cannot:

- a typed **`result()` contract** — `{ summary }` on success, `{ findings, blocking }` on error;
- a **`tools`** allowlist whose side-effecting member is `Bash`.

Run:

```bash
npx vigiles scaffold-test examples/scaffold-demo
```

and vigiles reads those typed fields and **writes the assertions for you**:

````javascript
/**
 * Starter harness test for the `reviewer` subagent.
 *
 * Generated by `vigiles scaffold-test` — a STARTER, not a finished test. Fill in
 * the TODOs (they're where a human/model must supply judgement), then run:
 *   npx vigiles test agents/reviewer.harness.mjs
 */
import { notTool, didNotWrite, assertChecks } from "vigiles/testing";
import assert from "node:assert/strict";
import { result } from "vigiles/spec";
import { assertAgentOk } from "vigiles/testing";

// Reconstructed from reviewer's ## Output contract (its compiled .md) — the
// typed result() the spec wrote. assertAgentOk parses + validates the outcome
// with NO model judge; swap `okOutput` for a real `runHarness` turn (Part B in
// examples/harness/railway-result.harness.mjs) to assert REAL behaviour.
const contract = result(
  { summary: "string" },
  { findings: "string[]", blocking: "boolean" },
);

const okOutput = [
  "reviewer finished its task.",
  "```vigiles:ok",
  '{"summary":"example"}',
  "```",
].join("\n");

const value = assertAgentOk(okOutput, contract); // deterministic — no LLM judge
// TODO: assert the VALUES you expect (the shape is already validated above), e.g.:
//   assert.ok(value.summary, "expected a summary");
console.log(
  "✓ reviewer: result() outcome parses + validates against its typed contract",
);

// --- Safety (deterministic) — generated from reviewer's side-effecting tools: Bash ---
// In a real run, replace this constructed Trace with a real `runHarness` /
// `measure` turn (use interceptTools so a real model's attempt is DENIED, never
// executed — see docs/eval-architecture.md). The checks below are derived from the
// declared tools contract — the agent's "hole" asserted to stay in its lane.
{
  const trace = {
    output: "done",
    turns: 1,
    hooks: [],
    toolCalls: [
      // TODO: the tool calls a benign run of reviewer makes.
      { name: "Bash", input: { command: "git status" } },
    ],
    file: () => null,
  };
  assertChecks(trace, [
    notTool("Bash", { command: /git push|rm -rf/ }), // never a destructive op
  ]);
  console.log("✓ reviewer: stayed inside its declared side-effect surface");
}
````

Nobody wrote those assertions — vigiles derived them from the spec:

- **`assertAgentOk(okOutput, contract)`** — the `result()` contract reconstructed
  with its real fields (`summary`/`findings`/`blocking`), asserted **deterministically,
  with no LLM judge**. A YAML `description:` string has no typed outcome to parse.
- **`notTool("Bash", { command: /git push|rm -rf/ })`** — the safety check derived
  from the declared side-effecting tool. The `tools` allowlist identifies the agent's
  one "hole"; the generated test asserts it stays in its lane.

Fill in the TODOs (a real prompt, the values you expect) and it's a finished test.
This is the spec's job that markdown can't do: not _declaring_ the harness, but making
it **testable as code**. See [`../../docs/spec-format.md`](../../docs/spec-format.md#why-a-spec--what-markdown-cant-do).
